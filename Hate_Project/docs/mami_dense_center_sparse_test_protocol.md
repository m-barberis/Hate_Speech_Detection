# Approved dense-random, center and sparse-random MAMI test extension

The user approved this replacement for the proposed circle-only extension.
The new patterns are proposed recipes, not recovered historical implementations.
The original clean/grid evaluation remains unchanged and should finish first.

## Fixed inputs and patterns

Reuse all 1,000 frozen MAMI test originals, their per-meme unseen emoji identity,
class labels, original supplied transcriptions and prompts from
`data/processed/mami_lora_qlora_test_seed42`. Assign one pattern to each meme:

| Pattern | Emoji count | Side length / minimum image side | Memes |
|---|---:|---:|---:|
| Dense random | 16 | 0.25 | 334 |
| Center | 1 | 0.75 | 333 |
| Sparse random | 4 | 0.25 | 333 |

Assign patterns with fixed, approximately class-balanced shuffles (seed 42 for
class 0 and 43 for class 1): dense has 167 memes/class; center has 166/167;
sparse has 167/166. These are different subsets, not three presentations of every
meme. Pattern-level estimates have about 333 examples and greater uncertainty
than the aggregate 1,000-example mixture. The emoji assignment from the grid test
is retained; it is not rebalanced separately inside each small pattern subset.

Per-image random position seeds use SHA256 of seed 42, test ID and pattern.
Dense and sparse emojis fit wholly inside the image; integer top-left positions
are sampled independently and uniformly from the valid range. Overlap is allowed.
The center emoji is centered with integer coordinates. Rotation is zero, nominal
alpha is 0.8, and JPEG encoding uses the same defaults as the grid test. Resize,
alpha scaling, masked paste and final alpha-composite operations match the old
augmentation renderer. CPU tests compare the generalized renderer with the
original grid function pixel for pixel, including translucent source assets.
No historical parameter equivalence beyond reused rendering semantics is claimed.

This tests transfer beyond the grid augmentation used in adapter training.
Counts, placement, size, overlap and occlusion coverage differ, so performance
ordering does not isolate a pure geometry effect or equal corruption severity.
These evaluation emoji identities were also absent from adapter augmentation;
absence from base-model pretraining is not established.

## Commands after syncing the scripts folder

CPU preparation may run while the old GPU evaluation finishes:

```bash
nice -n 19 python scripts/mami_lora_qlora/prepare_unseen_patterns.py
```

It verifies the existing frozen source data and emoji hashes, renders exactly
1,000 overlays, and writes positions, pattern assignments, image hashes and two
prompt conditions under `data/processed/mami_unseen_patterns_seed42`.
It never overwrites the source preparation or an existing destination.

Once all four original test arms are complete and GPU 0 is available:

```bash
bash scripts/mami_lora_qlora/run_unseen_patterns.sh
```

The launcher requires all four old completion markers, uses nice 19, runs four
fresh sequential processes on the single approved V100, and stops on failure.
The new evaluator is separate from evaluate_test.py so the original running job's
source and recorded controls are unchanged. It reuses the original model-loading
recipe, training gates, checkpoint checks, scoring, and package controls. Adapter
hashes are verified after reload; do not merge adapters. Run two new conditions
per arm: 1,000 overlays without supplied text and 1,000 with original text.
There are 8,000 new predictions and no additional clean/grid generations.

Retain max_new_tokens=5, greedy decoding, single-example inference, original
processor limits, SDPA, FP16 compute and the same broad NF4 weight quantization.
No training, epoch selection, alpha sweep, rotations or hidden batch-size fallback.
Complete existing new arms may be verified and reused on launcher rerun; partial
existing arm directories are preserved and require inspection before retrying.
No per-example automatic resume is implemented. Nice only affects CPU priority.

The new evaluation results are under
`results/mami_lora_qlora/unseen-patterns-v1/`. Each arm saves metadata,
2,000 raw ordered predictions, per-condition aggregate metrics and a completion
marker. The final `comparison.json` contains all patterns' metrics, paired
model contrasts and per-arm pattern-minus-clean and pattern-minus-grid effects.

## Reusing predictions and analysis

Reuse all 1,000 clean predictions in each of the two prompt conditions for each
of four arms: 8,000 clean predictions already generated by the original test.
Its additional 8,000 grid predictions provide the matched layout reference.
Verify source data, true labels, completion/file hashes, base revision, trained
checkpoints, software, processor/image budget, adapter hash, generation controls,
scoring source and input signatures before combining outputs. Different evaluator
source hashes are intentional between the old and new suites; record both,
require source equality across arms within each suite, and do not require equality
between the two suites. Old summary outputs and predictions remain unchanged.

Report macro-F1, accuracy, invalid counts, confusion matrices and strict format
on the full fixed mixture and each pattern subset. For each subset, use exactly
that subset's clean/grid predictions for comparisons. Transcription-present
results remain primary, image-only results diagnostic. Invalid predictions are
errors and operational failures stop the job instead of becoming clean labels.

For adapted-minus-base and quantized-minus-FP16 model contrasts, and each
corruption contrast, bootstrap the same paired meme indices. Use 2,000 seed-42
replicates, stratified by true class and assigned pattern, retaining the fixed
mixture counts. Individual-pattern analysis uses class stratification within
that subset. Percentile 95% intervals are unadjusted pointwise intervals, not
formal equivalence or multiplicity-corrected claims. No equivalence margin or
practical-effect threshold was specified. Single-seed/split evaluation does not
measure training-run variability. All memes are held out of adapter training,
but 100 were previously used in inference benchmarking.

The extension contains half the number of new predictions as the original
16,000-prediction test; use observed per-arm timings from that run for an ETA.
Loading and input/token differences mean elapsed time need not be exactly half.
CPU tests cover assignments, pixel equivalence, bounded/repeatable placement and
paired bootstrap behavior. Actual GPU inference remains a server runtime check.
